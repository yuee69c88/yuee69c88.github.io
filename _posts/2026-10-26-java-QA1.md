# 一、基本类型

1. Java 有哪 8 种基本类型？ 它们各占多少位？为什么 `boolean` 的实际内存占用不能简单认定为 1 bit？
   提示：byte（1字节），short（2字节），int（4字节），long（8字节），float（4字节），double（8字节），char（2字节），boolean。内存的最小寻址单位是字节。字撕裂。对齐和字长。

2. 为什么 Java 的 `byte`、`short`、`char` 在算术运算时通常会提升为 `int`？ 这种提升规则与 CPU 指令、Java 语言规范分别有什么关系？
   提示：指令集、硬件、正确性

3. 为什么 `char` 是无符号类型，而其他整数基本类型都是有符号类型？ `char` 能否表示所有 Unicode 字符？为什么？
   提示：char的用途、历史语境、正确性、其他整数有符号

4. Java 的整数溢出为什么不会抛出异常？ `int` 达到最大值后再加 1 会发生什么？为什么这种行为与二进制补码有关？
   提示：硬件默认丢进位、数学上取模、检查成本、代价是什么。电路、补码和补码的作用。

5. Java 中隐式类型转换与显式类型转换的规则是什么？ 为什么 `long` 转 `float` 不需要强制转换，却可能丢失精度？
   隐式是拓宽、显式是窄化。float和long的量级范围。有效数字导致丢精度。

6. 为什么 `0.1 + 0.2` 不一定等于 `0.3`？ 请从 IEEE 754 浮点数的存储结构解释，而不是只回答“存在精度问题”。
   数学原因、存储结构、加法。

7. `float` 和 `double` 中的 `NaN`、正无穷、负无穷分别是如何产生的？ 为什么 `NaN == NaN` 为 `false`？它们的比较规则是什么？
   浮点运算的封闭性、比特层面、比较关系、Double.isNaN判断。

8. 为什么 `byte a = 1; a += 1;` 能编译，而 `a = a + 1;` 不能编译？ 请从表达式类型提升、复合赋值和隐式类型转换的角度解释。
   a + 1` 因为二进制数值提升，类型是 `int；`int` 赋给 `byte` 是收窄，需要显式强转；a += 1` 按语言规范等价于 `a = (byte)(a + 1)自带强转。

9. Java 基本类型在方法参数传递时采用什么机制？ 如果方法中修改传入的基本类型参数，为什么调用方的变量不会改变？
   方法调用时，实参的值被**拷贝**进新栈帧的局部变量表，成为形参。形参和实参是两个独立的存储位置。Java 只有值传递。

10. 对于一个被多个线程共享的 `long` 变量，普通读写、`volatile` 读写以及 `value++` 在原子性方面有什么区别？ 请结合 Java 内存模型解释。
    单次读写的原子性、可见性、复合操作的原子性，是三件不同的事。

11. 为什么 `byte a = 127` 可以编译，但 `byte a = 128` 不行？ 为什么某些 `int` 常量可以直接赋值给 `byte`，而普通 `int` 变量不可以？
    字面量 `127`、`128` 都是 `int`，赋给 `byte` 本质是收窄转换。**int 常量表达式**，且**值在目标类型范围内**，允许隐式收窄。常量的值编译期已知，编译器能**亲自证明**不会丢信息。

12. Java 基本类型的默认值是什么？ 为什么成员变量可以不显式初始化，而局部变量必须满足确定赋值规则？
    默认值都是全 0 比特读出来的值。成员变量和数组元素有默认值，是因为堆上分配时整块清零本来就是必须做的（代价低），并且这保证了**不会读到上一个对象留下的垃圾**。局部变量在栈帧里，不清零，一是每次调用都清零不划算，二是槽会被复用，三是给默认值会掩盖"忘了初始化"的 bug。

13. Java 的整数除法和浮点数除法有什么区别？ 为什么整数除以零抛异常，而浮点数除以零可以产生无穷大或 `NaN`？
    整数除法是向零截断，浮点除法是 IEEE 754 的"精确商再舍入到最近"。整数的每个比特模式都是合法数值，浮点格式预留了指数全 1 的编码。

14. Java 的 `>>` 和 `>>>` 有什么区别？ 为什么 `byte` 参与位移运算后结果是 `int`？为什么 `int` 右移 32 位相当于右移 0 位？
    `>>` 补符号位，是为了让补码下的右移等于 $\lfloor x / 2^n \rfloor$；`>>>` 把比特当无符号数。`byte` 变 `int`，是因为 JVM 只有 32 位和 64 位的位移指令，窄类型进栈就已扩展成 `int`。右移 32 位等于右移 0 位，是因为规范规定只取移位量的低 5 位，这是对硬件行为的固化。

15. 从 `double` 强制转换为 `int` 时究竟发生了什么？ 超出 `int` 范围、遇到 `NaN`、遇到正负无穷时分别如何处理？
    先向零截断小数部分，再看整数值装不装得下。`NaN` 得 0；超范围包括无穷，正的得 `MAX_VALUE`，负的得 `MIN_VALUE`。转 `byte`/`short`/`char` 是先转 `int`，再截断低位，所以可能出现"大正数变 -1"。`float` 转 `int` 规则完全相同，`double`/`float` 转 `long` 也一样，只是边界换成 `Long.MAX_VALUE`/`Long.MIN_VALUE`。

16. Java 三元运算符 `?:` 的结果类型如何确定？ 为什么它的类型推导不能简单理解为两个分支取范围更大的类型？
    类型是编译期由两个操作数的**静态类型**决定的，跟运行时选了哪个分支无关。先分类（布尔、数值、引用），数值型再走规则：同类型、`T` 对 `int` 常量、`byte`/`short`、二元提升。"取范围大"在 `short`/`char`、常量收窄、`long` 转 `float` 丢精度、拆箱 NPE 这四处都解释不了。实用建议：分支类型不同时，要么显式强转让两边一致，要么用 `if-else` 拆开，别指望靠三元表达式自动选对。

17. JVM 如何表示和操作基本类型？ `int`、`long` 在局部变量表中分别占几个槽位？Java 语言层面的类型大小是否等同于实际对象内存占用？

    槽位是 32 位：int、float、引用占 1 个，long、double 占 2 个，实例方法的 0 号槽位是 this。类型信息在操作码里，验证器在加载时静态检查，运行时槽位里只有裸比特。byte/short/char/boolean 在栈上和局部变量表里都是 int，只有存到字段和数组时才区分宽度。语言类型大小只定义值域；实际内存占用要加上对象头、对齐填充、字段重排，通常比字段大小之和大得多。

18. `Integer` 和 `int` 有什么本质区别？ 自动装箱、拆箱、整数缓存如何影响 `==` 的结果？拆箱为什么可能触发空指针异常？
    装箱拆箱是**编译器**的语法糖，不是 JVM 的特性。`int` 是值，`Integer` 是不可变对象，有身份、能为 `null`，存在的理由是泛型只能装对象。装箱就是 `Integer.valueOf(i)`，拆箱就是 `x.intValue()`，都是编译器插进去的。`valueOf` 对 $[-128, 127]$ 返回缓存对象，所以两个 `Integer` 用 `==` 比较时，127 为 `true`、128 为 `false`；比较值要用 `equals`。`Integer == int` 走数值比较（先拆箱），`Integer == Integer` 走引用比较。拆箱 NPE 的根源是：`null` 是引用的取值，不是 `int` 的取值，对它调 `intValue()` 必然失败。
